# 界面重设计：材质与逐屏改动

更新：2026-11-02。这是设计决策记录，不是已完成的功能清单——**代码一行没动**，
本文写的是"按哪套口径去改"。原型见对话内并排对照图（agent / 设备 / 消息 / 设置 四屏 × 两平台）。

## 已定的两条门槛口径

| 平台 | 材质 | 决策 |
| --- | --- | --- |
| 安卓（Compose） | 背景高斯模糊近似玻璃 | **minSdk 30 → 31**，全量支持真模糊，不留降级分支 |
| iOS（SwiftUI） | 系统液态玻璃 | 保持 deploymentTarget 17.0，**逐处写可用性分支**：iOS 26 走系统材质，17–19 走降级档 |

**Why：** 两边门槛不对称。安卓只差一档（模糊需要 Android 12 / API 31，工程现设 minSdk 30），
抬一档就能全量支持，代价是放弃安卓 11 用户——而 README 里写的"最低安装版本 Android 11"就是这一行决定的。
iOS 差 9 个版本，抬门槛等于丢掉绝大多数用户，只能双轨。

**How to apply：** 改任何一处玻璃前先问"这一处在安卓 11 上要不要活"——按现在的决策答案是"不用"，
所以安卓侧直接调用系统模糊，不写 fallback；iOS 侧必须写。**降级档是两边的共同基线**：
没有玻璃时两个平台的观感几乎一致，所以设计稿只出一份。

## 材质矩阵：哪一层用什么

模糊是有代价的，不是所有表面都值得。

| 表面 | 安卓 | iOS | 说明 |
| --- | --- | --- | --- |
| 左侧设备栏 | 真模糊 | 液态玻璃 | 常驻、不滚动，采样成本固定 |
| 底部导航栏 | 真模糊 | 液态玻璃 | 同上；iOS 的选中态用系统那套形变容器 |
| 悬浮输入条 | 真模糊 | 液态玻璃 | 内容从它下方滚过，模糊才有意义 |
| 实时画面小窗 | 真模糊 | 液态玻璃 | 现有实现已经用半透明底，加一层模糊即可 |
| **对话气泡** | **纯色底** | **纯色底** | **长列表滚动最频繁的一屏，逐卡实时采样会掉帧**；用现成的 answer 令牌 |
| 设备网格卡 | 真模糊 | 液态玻璃 | 屏短、卡片数少，可承受 |

**Why：** 原型里为了好看，气泡也加了模糊；落地时按这张表执行，别照原型抄。
中低端安卓机上滚 agent 页是最容易暴露掉帧的路径，这条是性能判断，不是审美偏好。

## 逐屏改动清单

四栏结构（设备 / agent / 消息 / 设置）不动，它写死在 `app/src/main/java/com/wangzan101/mika/ui/FleetShell.kt`
的导航里；左设备栏与对话流的结构沿用 `ChatDrawer.kt`。改的是材质层与三处信息密度。

1. **设备页**（`FleetRadar.kt`）：顶部两行文字计数（已连接数 / 附近设备数）改成一条主操作胶囊；
   每台设备一张卡，连接状态用头像外圈表达——蓝闪＝执行中、绿＝在线空闲、灰＝离线；
   失败原因写在卡片第二行，不弹 toast。
2. **agent 页**（`ChatDrawer.kt`、`ChatScreen.kt`）：任务卡内加一条步骤流（已完成步 / 当前步 / 剩余步）
   与"第 n / m 步"。现在只有一行"正在处理 加耗时"，看不出走到哪。
3. **消息页**（`FleetMessages.kt`）：设备筛选提到第一层做成横滑；系统级"需要你处理"的提醒与聊天消息分开放。
   回复输入条常驻写明"将由哪台设备的 agent 发出"。
4. **设置页**（`FleetManagement.kt`）：作用范围改成常驻胶囊（批量改设备时选错范围是最贵的错）；
   失败设备单独成卡，写明哪台、哪一项、当前实际状态。

## 配色口径：克制优先

2026-11-02 追加。上一版原型被判定"太鲜艳"，这一节写清砍了什么、为什么，避免下次又加回来。

**最终口径（已落到代码）：整条色相只用紫，深浅是明度翻转。** 定稿走的是"浅紫 + 透明"那一档，
不是先前试过的"砍形状换中性灰白"——形状、布局、四栏结构一律保留。

| 换掉的 | 换成 | 落在哪 |
| --- | --- | --- |
| 蓝 / 绿 / 橙 / 红 / 紫并存的系统彩色 | 单色相（紫）token：accent `#6D41D2`、ok `#524474`、warn `#645A7C`、bad `#7147D1`（深色下同一色相提亮：`#9C8FD6` / `#A9A2C0` / `#C0B6DE` / `#C4A9F0`） | 安卓 `ui/theme/Colors.kt`；iOS `Shared/FleetPalette.swift` |
| 彩色壁纸底 | 同色相纵向渐变：浅 `#FAF8FE → #DCD7EE`，深 `#241F35 → #0C0A14` | FleetWallpaper（两端各一份，安卓 `Glass.kt`、iOS `ios/Shared/FleetPalette.swift`） |
| 头像逐机色相旋转 | 色相统一旋到紫带，设备靠**形状与明度**区分 | `ios/App/AoraAnimatedAvatar.swift` 的 filter |
| 状态靠颜色读 | 状态靠点位、字重、图标读；同一色相内只差明度 | 所有 `chip` / 状态点 |
| 到处实心不透明 | 常驻三条边（导航栏、输入条、设备侧栏）用玻璃；滚动区卡片用半透明不采样背景 | 安卓 FleetGlassSurface / iOS fleetGlass，滚动区用 fleetPanel |

**Why：** 玻璃看着花，八成是背景带的，不是玻璃本身；一屏里同时出现四五种色相才是"鲜艳"的来源。
目标是苹果那种安静大方，而不是仪表盘那种靠信息密度堆出来的专业感。

**How to apply：** 加任何彩色前先问"这一屏现在有几处彩色"——超过一处就换掉。
新代码不许写 `Color.mint` / `.orange` / `#RRGGBB` 这类字面量，一律取 token；
安卓侧 `Colors.kt` 顶部那条 HUD-1 注释就是给这件事兜底的。

## 新增的内容只有一处

结果状态徽标：**已核实 / 未核实 / 不通过**。

- 未核实＝执行端自报完成，中控没有证据；
- 已核实＝中控按可复查的读数核对过（前后对比、文件变化、判据退出码）；
- 不通过＝核对后与执行端的说法不一致。

**Why：** 这是整个衍生项目相对上游的增量所在，界面上没有出口的话，做出来也没人看得见。
上游现状是执行端回一句"已完成"就结束，没有任何一层判断是不是真做完了。
